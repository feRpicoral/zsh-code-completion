# zsh-code-completion

Tab completion for `code`, the [Visual Studio Code CLI](https://code.visualstudio.com/docs/configure/command-line), in zsh. Completion only: no aliases, no wrapper functions.

zsh ships a `_code` of its own, but it predates the `chat`, `serve-web`, `agent` and `tunnel` subcommands and many newer flags. VS Code's terminal IntelliSense does know the current CLI, but only inside VS Code's integrated terminal. This plugin gives any terminal an up-to-date completion.

`_code` is generated by running the CLI's own help (`code --help`, `code tunnel --help`, ...) and parsing it. It reflects the version in [`code-version`](code-version). A scheduled workflow regenerates it against the latest stable release every day and opens a pull request when something changed.

## What it completes

- Files and folders to open, as `code` normally takes
- The `chat`, `serve-web`, `agent` and `tunnel` subcommands and everything nested under them (`code tunnel user login`, `code tunnel service install`, `code agent host`, ...), with descriptions
- Flags for the root command and for each subcommand, including short forms such as `-d`, `-n` and `-r`
- Values the help spells out: `--log`, `--sync`, `--locate-shell-integration-path`, `chat --mode`
- Installed extension ids for `--uninstall-extension`, `--disable-extension` and `--enable-proposed-api`, read from `code --list-extensions`
- Files and directories for flags that take a path, including `.vsix` files for `--install-extension`

Marketplace extension ids, profile names and locales are not completed.

## Installation

### Oh My Zsh

```bash
git clone https://github.com/feRpicoral/zsh-code-completion.git \
  ${ZSH_CUSTOM:-~/.oh-my-zsh/custom}/plugins/zsh-code-completion
```

Add it to the plugins array in `~/.zshrc`:

```bash
plugins=(... zsh-code-completion)
```

Then reload the shell:

```bash
exec zsh
```

### Other plugin managers

Load `zsh-code-completion.plugin.zsh` the way your manager loads any plugin. It adds the directory to `fpath` and registers the completion itself when `compinit` has already run.

### Manual

The directory has to come before zsh's own functions in `fpath`, or the bundled `_code` wins:

```bash
git clone https://github.com/feRpicoral/zsh-code-completion.git
```

```bash
fpath=(/path/to/zsh-code-completion $fpath)
autoload -Uz compinit && compinit
```

## Development

The generator needs Node (see `.nvmrc`) and an installed VS Code. It has no dependencies of its own.

Regenerate from the `code` on your `PATH`, or from a specific launcher:

```bash
scripts/update.sh
```

```bash
scripts/update.sh "/Applications/Visual Studio Code.app/Contents/Resources/app/bin/code"
```

Run the tests, which drive a real interactive zsh through a pty and check what it offers:

```bash
scripts/test.zsh
```

The CLI prints two help formats: VS Code's own for the root command and `chat`, and a different one for `serve-web`, `agent` and `tunnel`, which a separate binary handles. The generator parses both. Both state which flags take a value, so nothing is guessed there; what a value completes to is decided from the name the help gives it.

`_code` is generated from the macOS build, in CI as well, so that local and automated runs produce the same file.

## Troubleshooting

If completions do not show up after installing, rebuild the completion cache:

```bash
rm -f ~/.zcompdump*
exec zsh
```
